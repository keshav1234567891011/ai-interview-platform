# AI-assisted interviewing

AI assistance is optional and off by default. Candidates explicitly opt in during session setup after seeing what is shared. Existing sessions remain curated. With `OPENAI_API_KEY` configured in ignored `backend/.env`, opted-in sessions request one question at start and one after each submitted answer. Without a key, or after an error, the curated question bank remains usable. Draft saves and reading a session never call the provider.

The provider boundary uses the official OpenAI Python SDK's Responses API with Pydantic structured output, a fixed HTTPS endpoint, disabled environment proxy overrides, `store=False`, no automatic retries, and a configurable 15-second request timeout. `OPENAI_MODEL` defaults to `gpt-5-mini`; model access depends on your OpenAI project. API usage may incur charges. Automated verification uses mocks only.

Context includes the role, requested level, canonical skills, focus areas, profile summary (up to 1,200 characters), latest resume and job excerpts (up to 4,000 characters each), prior prompts, and up to three recent answers (2,000 characters each). Names, email addresses, storage paths, and application secrets are not deliberately included. Resume/job text can contain personal information: review your documents before opting in. Provider processing and retention policies still apply; `store=False` does not promise zero retention.

Untrusted content is JSON-escaped in a separate user message with explicit delimiters. The system instruction prohibits treating it as instructions and forbids hidden prompt disclosure, answers, scores, sensitive personal questions, and tools. These measures reduce prompt-injection risk; they do not prove model behavior safe. Output must pass strict field, length, category, role-relevance, requested-level, and duplicate checks before persistence. The application renders question text as ordinary escaped React text.

Adaptive difficulty is a transparent effort heuristic, **not correctness evaluation**: fewer than 20 words invites a foundational prompt; at least 80 words, 35 distinct words, and two reasoning markers can invite a harder prompt. Other answers keep the selected level. It can be gamed and does not infer competence. Levels stay bounded, and curated fallback respects the level where coverage allows. Exact normalized duplicates and high token-overlap paraphrases are rejected; this is not a complete semantic duplicate detector.

Provider timeouts, rate limits, refusals, malformed output, and other exceptions leave saved answers and the preselected fallback intact. Raw provider errors are never returned or logged. PostgreSQL row locks serialize updates, including the bounded provider request. For higher traffic, asynchronous generation outside the transaction and shared throttling/budget controls are later deployment work. Detailed scoring and evaluation are intentionally deferred.

Primary implementation references: [structured output](https://developers.openai.com/api/docs/guides/structured-outputs), [official Python SDK and timeouts](https://github.com/openai/openai-python), and [GPT-5 mini capabilities](https://developers.openai.com/api/docs/models/gpt-5-mini).
