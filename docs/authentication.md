# Authentication decisions

Normalized unique emails and UUID IDs identify accounts. Passwords use pwdlib's recommended Argon2 implementation. JWTs remain in HttpOnly cookies scoped to `/api`, SameSite=Lax, Secure in production. Explicit Bearer credentials are supported for non-browser clients.

Writes require `X-InterviewAI-Request: 1`. Provided Origin headers must match explicit configured origins. Cross-site simple forms cannot supply the required header, and credentialed CORS has no wildcard. Production requires HTTPS and a same-site deployment. These protections do not replace XSS prevention.

Token expiry and session versions are checked against the database. Logout revokes all existing account sessions. No refresh-token, email verification, or password recovery workflow is claimed. Duplicate registration emails are explicit; login failures are generic. Per-process throttling requires shared ingress protection in multiworker production deployments.

Missing database/JWT settings leave the app importable and health available; account features report HTTP 503. Validation errors exclude raw request inputs. No production secret is generated by setup.

See the official [FastAPI security guide](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/) and [Starlette cookie documentation](https://starlette.dev/responses/). Tests exercise real ASGI routes and isolated SQLite persistence; migrations also compile for PostgreSQL offline. Live PostgreSQL requires manual configuration.
